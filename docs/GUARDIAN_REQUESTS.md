# ขั้นตอนรับคำขอเกี่ยวกับผู้เยาว์

สถานะ: ผู้ดูแลยืนยันรับผิดชอบขั้นตอนนี้เมื่อ 25 ตุลาคม 2569 ยังไม่ใช่การยืนยันว่าได้ตรวจอำนาจปกครอง
ของผู้ใช้ปัจจุบัน หรือคำรับรองว่าบริการผ่านการตรวจทางกฎหมายแล้ว

Newbiegrader รับสมัครได้ทุกวัยตามการตัดสินใจของผู้ดูแล ไม่ใช้เกณฑ์อายุ 13 หรือ
18 ปีที่ตั้งขึ้นเองแทนกฎหมาย และไม่ถือว่าการกดสมัคร การยืนยันอีเมล หรือการติ๊ก
ยอมรับข้อกำหนดพิสูจน์อายุหรืออำนาจปกครองได้

เมื่อใช้ฐานความยินยอม มาตรา 20 มีเงื่อนไขเฉพาะสำหรับผู้เยาว์ รวมถึงกรณีอายุ
ไม่เกินสิบปี ส่วนฐานในการประมวลผลข้อมูลต้องพิจารณาตามวัตถุประสงค์จริง ไม่ใช่
ถือว่าทุกอย่างใช้ความยินยอมหรือใช้สัญญาได้โดยอัตโนมัติ อ้างอิง
[ตัวบทที่เผยแพร่โดยกรุงเทพมหานคร](https://webportal.bangkok.go.th/public/user_files_editor/435/PDPA-PRB62.PDF)
มาตรา 19, 20, 23 และ 24 และ
[แนวทางการขอความยินยอมที่เผยแพร่โดยกระทรวงดิจิทัลฯ](https://www.mdes.go.th/law/detail/6045)
ตรวจแหล่งข้อมูลวันที่ 25 ตุลาคม 2569

## ผู้รับผิดชอบและการรับเรื่อง

ผู้ดูแลโครงการเป็นผู้พิจารณา ส่งคำขอส่วนตัวถึง `newbiegrader.team@gmail.com`
หัวข้อ “ผู้ปกครองและบัญชีผู้เยาว์” อย่าใช้ issue สาธารณะ และอย่าส่งรหัสผ่าน OTP
สำเนาบัตรประชาชน หรือเอกสารของเด็กมาในข้อความแรก

รับข้อมูลเท่าที่จำเป็น: อีเมลบัญชีที่เกี่ยวข้อง ช่องทางตอบกลับของผู้ขอ
ความสัมพันธ์/ฐานะผู้ใช้อำนาจปกครอง และเรื่องที่ต้องการให้ช่วย ใช้ช่วงอายุเมื่อ
จำเป็นต่อการพิจารณา ไม่ขอวันเกิดเต็มหรือเลขประจำตัวเป็นค่าเริ่มต้น

## ลำดับการพิจารณา

1. เปิดเลขอ้างอิงกรณีส่วนตัว ตรวจว่าผู้ขอควบคุมช่องทางติดต่อของตนได้ การยืนยัน
   อีเมลยืนยันได้เพียงการควบคุมกล่องจดหมาย ไม่ได้ยืนยันอำนาจปกครอง
2. แจ้งข้อมูลที่เก็บ ระยะเก็บ ผู้ให้บริการ และการที่สมาชิกอื่นอาจดูโค้ดคำตอบที่
   เข้าเงื่อนไขได้ ใช้ Privacy/Terms ฉบับที่เปิดใช้อยู่ ให้เด็กเข้าใจตามวัยด้วย
3. ผู้ดูแลพิจารณาฐานประมวลผลและความจำเป็นของความยินยอมสำหรับกรณีนั้น หากต้อง
   ตรวจอำนาจเพิ่มเติม ให้ตกลงช่องทางที่ปลอดภัยและหลักฐานขั้นต่ำกับผู้ขอก่อน
   ไม่อนุมัติอัตโนมัติเพราะใช้นามสกุลเดียวกัน เป็นครู หรือยืนยันอีเมลสำเร็จ
4. ถ้าข้อเท็จจริงหรือฐานกฎหมายยังไม่ชัด ให้พักการพิจารณาและปรึกษาผู้มีความรู้
   ที่เกี่ยวข้อง ไม่เปิดเผยข้อมูลบัญชีให้บุคคลที่ยังตรวจสิทธิไม่ได้ และไม่อ้างว่า
   มีระบบปิดบัญชีรอผู้ปกครองอัตโนมัติซึ่งยังไม่ได้สร้าง
5. บันทึกผู้ตรวจ เวลา รุ่นของนโยบาย วิธี/ผลตรวจอำนาจ วัตถุประสงค์และขอบเขต
   ที่อนุญาตหรือเหตุผลที่ยังอนุมัติไม่ได้ แจ้งผลให้ผู้ขออย่างชัดเจน
6. รับคำขอถอนความยินยอม แก้ไข หรือลบผ่านช่องทางเดิม ตรวจสิทธิผู้ขอใหม่ตาม
   ความเสี่ยง และดำเนินการกับข้อมูลเว็บพร้อมเอกสารกรณีที่อยู่นอกเว็บด้วย

## การเก็บและล้างเอกสารกรณี

เก็บบันทึกขั้นต่ำเป็นข้อมูลบัญชีในที่เก็บส่วนตัวที่จำกัดผู้ดูแล ตลอดเวลาที่
บัญชีใช้งาน และลบข้อมูลระบุตัวตนของกรณีเมื่อบัญชีถูกลบ ไม่ใส่ใน Git, Vault,
public audit หรือเครื่องประมวลผลโค้ดของผู้ใช้ เอกสารพิสูจน์ที่ได้รับมาให้ลบหลัง
ตรวจเสร็จเมื่อไม่จำเป็นต้องเก็บฉบับเต็ม เก็บเพียงวิธีและผลตรวจตามความจำเป็น

ผู้ดูแลรับผิดชอบตรวจคำขอและล้างเอกสารนอกเว็บควบคู่กับการจัดการบัญชี
API ลบบัญชีไม่สามารถลบอีเมลหรือเอกสารส่วนตัวของผู้ดูแลแทนได้ จึงต้องแจ้ง
ข้อจำกัดและช่องทางขอลบให้ตรงกันใน Privacy ก่อนเก็บข้อมูลเพิ่มเติม
ห้ามอ้างว่าระยะเก็บเอกสารนอกเว็บนี้บังคับใช้อัตโนมัติแล้ว

ก่อนรับเอกสารกรณีแรก ผู้ดูแลต้องกำหนดที่เก็บส่วนตัวและรอบตรวจที่ใช้งานจริง
และทบทวนข้อความสาธารณะให้ตรงกับวิธีรับเรื่อง
การทบทวนเอกสารนี้ไม่ใช่การทดสอบผู้เยาว์จริงหรือการตรวจอำนาจปกครองจริง
